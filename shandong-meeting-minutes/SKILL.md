# 山东公司生产月度会议纪要生成器

## 概述
从钉钉导出的会议逐字稿（或其他会议文字稿/录音稿）自动生成符合山东公司公文规范的 **Word (.docx)** 会议纪要。

**触发词**：会议纪要、生产会纪要、月度会议纪要、生成纪要、生产运维会纪要、生产营销会纪要、钉钉会议纪要、整理会议记录、改写会议纪要

## 输入要求
用户需提供以下任一形式的输入：
1. 钉钉导出的会议文字稿（.txt / .md / 直接粘贴文本）
2. 会议录音转文字稿
3. 手动记录的会议笔记

**可选附加材料**（如提供则参照其格式和术语）：
- 往期标准会议纪要（.docx），用于参考术语和行文风格

## 输出格式
生成 **Word (.docx)** 文件，严格按照山东公司日常文稿规范排版。

## 会议纪要标准结构

根据实际已发布的会议纪要（参考2025年3月-12月共9份纪要），当前标准结构如下：

### 标题
```
山东公司YYYY年M月生产营销工作会纪要
```
> 注：2025年3-5月会议名称为"生产运维工作会"，8月起统一为"生产营销工作会"。今后默认使用"生产营销工作会"。

### 开篇段落（固定模板）
```
YYYY年M月D日，山东公司副总经理[主持人姓名]通过远程会议系统主持召开了[M]月份生产营销工作会议。会议听取了生产管理部、电力营销部、集控中心、[安质环部]、[海上基地公司]以及典型场站关于近期区域整体安全生产及营销工作的有关汇报，并对后续安全生产工作及重点关注事项作了安排部署。纪要如下：
```

### 第一部分：生产营销工作完成情况

#### （一）年度PBA核心指标完成情况
**生产运维方面**：事故起数、线路/设备分类、累计上网电量及完成率（基础值/基准值）、超发/欠发电量、限电量及限电率（同比变化）、长停机组台次、中电联风电/光伏小时数及绝对竞争力。

**电力营销方面**：交易电量、度电收入（风电/光伏分列）、全电量场站度电收入与区域平均对比、增收金额等。

#### （二）重点工作进展（可选，视会议内容而定）
列出各项重点工作的具体进展，编号排列。典型内容包括：
- 资本化项目推进情况（立项/招采/施工/完工数量）
- 设备治理进展（主轴、叶片、螺栓检测等）
- 技术监督、集控检查、无人值守建设等

### 第二部分：后续安全生产工作安排
**按编号排列**，每条以"1. 2. 3. …"格式依次列出。每条通常以**主题句开头（加粗或自然强调）**，后续展开具体工作部署。典型主题包括：
- 安全生产管理（隐患排查、"倒掉烧"专项、红线合规等）
- 设备安全治理（大部件、集电线路、SVG、储能等）
- 电量任务冲刺/经营管理
- 资本化项目/技改推进
- 电力营销（两个细则、功率预测、限电管理等）
- 成本与物资管理
- 无人值守/检修中心建设
- 人才培训与能力提升
- 参会部门提醒事项
- 廉洁从业
- 员工关爱与团队建设

### 第三部分：参会信息
```
出席：[主持人姓名]、[按职务排序的参会人员名单]，生产管理部全体人员。
记录：[记录人姓名]。
```

## 执行流程

### 第1步：读取输入
- 接收会议逐字稿（文本文件或直接粘贴的文本）
- 如果用户同时提供了往期标准纪要作为参考，一并读取

🔴 **CHECKPOINT**：确认逐字稿包含有效文本内容（非空文件）。如果为空，停止流程并提示用户。

### 第2步：信息提取与分类
从逐字稿中提取以下关键信息并分类：
- 会议日期、主持人
- PBA指标数据（事故数、电量、超欠发、限电率、中电联小时数等）
- 营销数据（交易电量、度电收入、区域对比等）
- 各场站汇报的重点工作进展
- 领导部署的后续工作安排
- 参会人员名单
- 记录人

### 第3步：术语修正
遍历全文，将钉钉语音识别常见错误按上述术语表逐项修正。

### 第4步：内容重构与润色
- 将口语化表达改写为正式公文语言
- 同类事项归类合并（如多个场站汇报的同类设备问题合并为一个段落）
- 领导部署事项按主题归类，归类规则如下：
  - **安全类**：隐患排查、事故学习、红线合规、两票管理、防台防汛、消防、应急演练 → 归入安全生产管理
  - **设备类**：大部件（主轴/叶片/齿轮箱）、集电线路跳闸、SVG、储能设备、螺栓检测 → 归入设备治理
  - **电量类**：发电量冲刺、限电管理、功率预测、AGC调试 → 归入电量任务
  - **营销类**：电价策略、两个细则考核、绿电/绿证、储能收益 → 归入电力营销
  - **管理类**：资本化项目、成本物资、无人值守、检修中心、人员培训、廉洁从业 → 归入管理事项
- 保持原文的关键数据不丢失、不篡改
- 删除口语填充词、重复表述

🛑 **STOP — 生成前审核**：重构完成后，必须将完整纪要文本展示给用户确认，或至少自检以下三项：(1) PBA数据是否与原文一致；(2) 第二部分是否全部带序号；(3) 出席/记录是否完整。确认无误后再进入第5步。

### 第5步：生成 .docx 文件
使用 python-docx 生成 Word 文档，严格按上述排版格式设置字体、字号、缩进、行距。

> **字体缺失处理**：如果系统没有"方正小标宋简体"，标题改用"宋体"加粗二号居中，并在生成后提示用户手动替换字体。

生成文件名格式：`山东公司YYYY年M月生产营销工作会纪要.docx`

🔴 **CHECKPOINT**：生成后读取 docx 验证：(1) 标题是否为方正小标宋/宋体二号居中；(2) 正文是否为仿宋_GB2312三号；(3) 第二部分是否含序号；(4) 文件可正常打开。任一不通过 → 修复后重新生成。

### 第6步：输出与保存
- 将 .docx 文件保存到工作目录
- 交付文件给用户

## 异常处理与兜底策略

执行过程中遇到以下情况时，按指定分支处理，**不允许静默跳过或自行编造**。

| 异常场景 | 触发条件 | 处理动作 |
|----------|----------|----------|
| 日期缺失 | 逐字稿未包含会议具体日期（日） | 在开篇段落用 `[  ]` 占位，**并在纪要交付时明确提醒用户手动填入**，不自行猜测日期 |
| PBA数据不完整 | 逐字稿缺少事故起数/上网电量/限电率等标准指标 | 从现有数据尽力重构PBA段落；缺失项留空不编造；在交付时列出缺失项清单 |
| 主持人无法确定 | 逐字稿未明确提及主持人 | 默认使用张锋（2025年8月起主持人）；交付时标注"主持人以实际为准" |
| 记录人缺失 | 逐字稿未提及记录人 | 默认填写"曹厚德"，交付时提醒确认 |
| python-docx 未安装 | `import docx` 失败 | 自动执行 `pip install python-docx`；安装失败则告知用户手动安装 |
| 字体缺失 | 系统无"方正小标宋简体" | 标题降级为宋体加粗二号居中；生成后在纪要正文末尾添加提示"请手动替换标题字体为方正小标宋简体" |
| docx 生成失败 | `doc.save()` 抛出异常 | 输出错误信息；检查 Python 脚本语法；修复后重试；连续3次失败则终止并报告 |
| 文件被占用 | `PermissionError` 保存时文件锁定 | 自动在文件名后加 `_v2` / `_v3` 后缀，最多重试3次 |
| 术语修正冲突 | 同一处匹配多条术语规则 | 优先匹配最长字符串（如"莱州盐光"优先于"盐光"） |
| 空逐字稿 | 输入文件无有效文本内容 | 停止流程，提示用户"逐字稿无有效内容，请检查文件" |

## 生成 docx 的 Python 脚本

```bash
python scripts/generate.py <output_path.docx>
```

其中 `section1_content` 和 `section2_content` 为列表，每项为 `{'type': 'heading2'|'body', 'text': '...'}`。

## 注意事项

### 数据准确性
- PBA指标数据必须与逐字稿一致，不编造数字
- 百分比和完成率保留一位小数（如"103%"、"97.5%"）
- 电量单位统一为"亿度"或"万千瓦时"（视上下文而定）

### 语言风格
- 正式公文语气，避免口语化
- 使用"请""需""应""将"等正式措辞，不用"要""得""可以"
- 领导部署事项保持原文指令性语气

### 结构灵活性
- "重点工作进展"子节为可选项，根据实际会议内容决定是否保留
- 如会议内容涉及特殊专题（如清明节部署、应急专项等），结构可适当调整

### 主持人识别
- 2025年3-7月主持人：王先军（副总经理、运维总监兼安全总监）
- 2025年8月起主持人：张锋（副总经理）
- 如逐字稿明确提到其他主持人，以逐字稿为准

### 字体备选
如果生成环境没有"方正小标宋简体"，标题使用"宋体"加粗二号居中替代，并在交付时提醒用户手动替换字体。

## 禁止事项（反例黑名单）

执行纪要生成时，以下行为**严格禁止**：

| # | 禁止行为 | 原因 | 正确做法 |
|---|----------|------|----------|
| 1 | **编造PBA数据** | 数据造假影响决策 | 缺失数据留空标注"（暂缺）"，不编造数字 |
| 2 | **改变发言人原意** | 纪要必须忠实于会议内容 | 可润色语言但不可增删实质性内容 |
| 3 | **跳过术语修正步骤** | 钉钉识别错误未被修正导致专业名词错误 | 生成前必须遍历全文，按术语表逐项替换 |
| 4 | **混用口语/公文语体** | 破坏纪要正式性 | 口语"要""得""可以"→公文"请""需""应""将" |
| 5 | **丢失关键数据** | 电量/电价/完成率等核心指标遗漏 | 第2步提取后与原文二次核对 |
| 6 | **使用错误的会议名称** | 2025年8月后统一为"生产营销工作会" | 2025年8月起不使用"生产运维工作会" |
| 7 | **第二部分不加序号** | 与公司纪要格式不一致 | 第二部分每条必须以"1. 2. 3. …"开头 |
| 8 | **正文使用错误字体** | 公司规范明确要求仿宋_GB2312，非"仿宋" | 检查字体名称为"仿宋_GB2312"（注意下划线） |
| 9 | **混用中英文标点** | 公文格式要求全角中文标点 | 逗号用"、"或"，"，引号用""" |
| 10 | **假设用户知道缺失信息** | 日期/人名等缺失时用户可能未察觉 | 缺失信息必须在交付时显式标注提醒 |
