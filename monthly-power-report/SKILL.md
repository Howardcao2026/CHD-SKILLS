# 月度电量生产分析报告生成器

## 概述

从3个Excel文件自动生成山东公司月度电量生产分析报告的完整流水线。
输出一份含ECharts可视化图表的自包含HTML报告。

## 输入文件要求

用户需提供3个Excel文件（通常放在桌面）：

1. **山东公司电量计划（包利润使用）.xlsx** — 年度电量计划表
2. **{YYYY-MM}_山东公司_风电_生产月报明细.xlsx** — 风电生产月报
3. **{YYYY-MM}_山东公司_光伏_生产月报明细.xlsx** — 光伏生产月报

## 入口判断：完整报告 vs 快速查询

在执行任何流程前，先判断用户意图：

**快速查询模式** — 触发条件（满足任一）：
- 用户明确说"只问一个数"、"不需要完整报告"、"帮我查一下XX"
- 用户只问单一指标（限电率、发电量、上网电量、完成率等），无"生成报告"意图

快速查询做法：
- 直接读取对应 Excel 文件的"山东公司合计"行
- 使用正确的公式计算（限电率=限电量/(限电量+发电量)，不是限电量/发电量）
- 直接回答数值，不启动任何脚本，不生成 HTML

**完整报告模式** — 触发条件：
- 用户要求"生成月报"、"出报告"、"月报分析"
- 用户一次性提供或提及3个Excel文件
- 明确需要完整的分析报告

完整报告模式下，执行以下6步流程。

## 执行流程

### Step 1：确认文件与月份

从文件名中提取报告月份（如 `2026-04`），确认3个文件均存在。如果文件路径不同，
让用户指定。不要猜测文件位置。

**异常处理**：
- 文件不存在 → 告知用户哪个文件缺失，询问正确路径，不做猜测
- 非标准文件名 → 接受用户指定的任何文件名，不尝试自动映射
- 目录不存在 → 停止，告知用户，不自动回退到桌面搜索

🔴 **CHECKPOINT · 🛑 STOP**：列出已确认的3个文件路径及报告月份，等待用户确认后再进入 Step 2。

### Step 2：复制并适配数据生成脚本

将 `scripts/generate_data.py` 复制到工作目录。

**STEP 2 完整改动清单（以当前报告月为 N 月，4月→5月为例）**：

| # | 改动项 | 搜索/定位 | 替换为 | 是否必须 |
|---|--------|-----------|--------|----------|
| 1 | 计划表文件路径 | `pd.read_excel('...电量计划'` | 用户提供的计划表路径 | ✅ |
| 2 | 风电月报文件路径 | `pd.read_excel('...风电'` | 用户提供的风电月报路径 | ✅ |
| 3 | 光伏月报文件路径 | `pd.read_excel('...光伏'` | 用户提供的光伏月报路径 | ✅ |
| 4 | `plan_{N-1}yue` 键名 | `plan_4yue` | `plan_5yue` | ✅ |
| 5 | `plan_cum_{N-1}` 键名 | `plan_cum_4` | `plan_cum_5` | ✅ |
| 6 | 累加公式（plan_cum） | `'1季度合计'] + (row['4月']` | `'1季度合计'] + (row['4月'] + (row['5月']` ` | ✅（N>4时必须手动添加 {4月+5月+...+N月}） |
| 7 | `plan_{N-1}yue` 变量名 | `plan_4yue` | `plan_5yue` | ✅ |
| 8 | `plan_cum_{N-1}` 变量名 | `plan_cum_4` | `plan_cum_5` | ✅ |

> ⚠️ **不改动的部分**：字段映射、计划值合并的累加逻辑、分类定义、公式计算 — 这些已多次验证，禁止改动。

**修改示例（4月→5月）**：
```python
# 改前（4月）
plan_cum_4 = plan_1q + plan_4yue

# 改后（5月）
plan_cum_5 = plan_1q + plan_4yue + plan_5yue  # 累加到5月
```
并将变量名 `plan_cum_4` 全局替换为 `plan_cum_5`。

其他所有逻辑（字段映射、计划值合并、分类定义、公式计算）**不要改动**，
这些已经过多次验证。

🔴 **CHECKPOINT · 🛑 STOP**：展示 plan_cum 累加公式（如 `plan_cum_5 = 1季度合计 + 4月 + 5月`）和3个文件路径，用户确认后再运行 Step 3。

### Step 3：运行 generate_data.py

```bash
python generate_data.py
```

产出 `analysis_data.json`。验证：
- JSON 包含 `plan_total`、`wind_plan_total`、`solar_plan_total`、`wind_total`、`solar_total`、`stations`
- 风电 stations 数量 ≈ 24，光伏 stations 数量 ≈ 6
- 公司整体数据 = 风电合计 + 光伏合计

**如果运行失败**：检查错误信息 → 是否pandas未安装（`pip install pandas openpyxl`）→ 是否文件路径有误 → 修复后重新运行。不要跳过此步骤。

### Step 4：复制并适配报告生成脚本

将 `scripts/gen_report.py` 复制到工作目录。

**STEP 4 完整改动清单（以当前报告月为 N 月，4月→5月为例）**：

| # | 改动项 | 搜索/定位 | 替换为 | 是否必须 |
|---|--------|-----------|--------|----------|
| 1 | 报告标题 | `2026年4月` | `2026年5月` | ✅ |
| 2 | 时间进度 | `33.33%` | `41.67%`（N/12） | ✅ |
| 3 | 时间进度说明 | `4个月/12个月` | `5个月/12个月` | ✅ |
| 4 | 累计标签（1-4月） | `1-4月` | `1-5月` | ✅ |
| 5 | 月份显示名（4月当月） | `4月当月` | `5月当月` | ✅ |
| 6 | `plan_4yue` → `plan_5yue` | 全文搜索 `plan_4yue` | 替换为 `plan_5yue` | ✅ |
| 7 | `plan_cum_4` → `plan_cum_5` | 全文搜索 `plan_cum_4` | 替换为 `plan_cum_5` | ✅ |
| 8 | 风速/辐照标签（4月→5月） | `4月风速`、`4月辐照` | `5月风速`、`5月辐照` | ✅ |
| 9 | 输出文件名 | `2026年4月` | `2026年5月` | ✅ |
| 10 | 页脚生成日期 | 日期字符串 | 当前日期 | 建议 |

> ⚠️ **不改动的部分**：图表 JS 代码、公式逻辑（限电率/场用电率/发电小时数）、CSS 样式、HTML 结构 — 这些已多次踩坑验证。
```python
# 标题

# 时间进度

# plan_cum引用

```

**不要改动：**
- 图表JS代码（ECharts配置已经过踩坑验证）
- 公式逻辑（限电率、场用电率、发电小时数）
- CSS样式和HTML结构

🔴 **CHECKPOINT · 🛑 STOP**：展示报告标题、时间进度、plan_cum 变量名等适配参数，用户确认后再运行 Step 5。

### Step 5：运行 gen_report.py

```bash

```

产出 `山东公司{YYYY}年{M}月电量生产分析报告.html`。

### Step 6：预览和交付

用 preview_url 打开HTML报告。**交付前先验证**：

1. 图表检查：滚动浏览全部8个章节，确认10个图表均有内容渲染（非空白）
2. 数据交叉验证：抽取3个关键数据点与月报原始合计行比对
   - 公司整体月上网电量
   - 风电累计上网电量
   - 光伏月发电量
3. 如果图表不显示，优先检查：
   - ECharts CDN 是否可访问（`https://cdn.jsdelivr.net/npm/echarts@5/dist/echarts.min.js`）
   - `<script>` 块中是否有 Python 语法残留（见下方"关键避坑规则"）

验证通过后交付报告。如果验证失败，回退到 Step 4 检查 gen_report.py 适配是否正确。

## 反例黑名单（绝不要做的事）

这些规则来自多次踩坑验证，每一条都曾导致报告数据错误或图表全部消失：

| # | ❌ 不要做 | ✅ 应该做 | 违反后果 |
|---|----------|----------|----------|
| 1 | 同名计划项目用字典覆盖 | 累加合并：`old[key] += entry[key]` | 计划值丢失，超欠发计算错误 |
| 2 | Python `if/else` 直接写进 JS f-string | Python 中预计算颜色变量，再插入 f-string | 全部 10 个图表消失 |
| 3 | ECharts series 上用 `function(p)` 回调设颜色 | 用 `data.map()` 在数据层预设 `itemStyle.color` | 图表无颜色显示 |
| 4 | 发电小时数 = 发电量 / 1.509 | 发电小时数 = 发电量(万kWh) / 装机容量(万kW) | 小时数完全错误 |
| 5 | 月份 ≥5 时，plan_cum 只加当月不减前月 | plan_cum_N = 1季度 + 4月 + 5月 + … + N月 | 累计计划值缺月，超欠发失真 |
| 6 | Step 3 跳过 JSON 结构验证 | 跑完 `generate_data.py` 后立即验证 JSON 字段完整性 | 后续 gen_report.py 崩溃无提示 |
| 7 | 在 gen_report.py 中"顺手优化" ECharts 配置 | 图表 JS 代码不动——CSS/样式也不动 | 已验证的图表配置被破坏 |
| 8 | 文件名手动拼接（如 `山东公司2026年5月` 硬编码） | 从用户提供的文件名提取月份，不做假设 | 报告标题与实际数据月份不一致 |
